# Домашно 4 — Генетичен алгоритъм (TSP / Knapsack)

## Описание

Да се имплементира генетичен алгоритъм (Genetic Algorithm, GA) върху **една** от следните две задачи:

- Задача 1 — TSP (задача за търговския пътник);
- Задача 2 — KP (задача за раницата).

## Задача 1 — TSP (търговски пътник)

### Описание

Да се реши задачата за търговския пътник (Traveling Salesman Problem) чрез използване на генетичен алгоритъм.

Целта е да се намери възможно най-краткият маршрут, който минава през всички точки точно по веднъж. Между всяка двойка точки съществува път. Началната точка няма значение – не е необходимо маршрутът да се връща в изходната позиция.

### Вход

Едно от следните:

1. Цяло число `N` (`N ≤ 100`) – генерирайте `N` произволни точки в равнината.
2. Име на набор от данни (низ с букви, може да съдържа и цифри), последвано от броя градове и редове с:

   ```
   <име_на_град> X Y
   ```

### Изход

1. Поне 10 стойности (по една на ред) – текущо най-добрата дължина на пътя в популацията: първо поколение, поне осем междинни, последно поколение.
2. Празен ред.
3. Най-доброто намерено решение:
   - При `N` случайни точки: само финалната дължина (една стойност), равна на последната от горния блок.
   - При именован набор: един ред с маршрута `CityA -> CityB -> ...`, следван от ред с финалната дължина.

   Финалната дължина трябва да съвпада с последната в горния блок и с преизчислената дължина на маршрута.

### Пример

**Вход:**

```
UK12
12
Aberystwyth 0.190032E-03 -0.285946E-03
...
Stratford 217.343 -447.089
```

**Изход:**

```
2426.8086
...
1595.7385

Aberystwyth -> Inverness -> Nottingham -> Glasgow -> Edinburgh -> London -> Stratford -> Exeter -> Liverpool -> Oxford -> Brighton -> Newcastle
1595.7385
```

### Бележки

- За случай 2 се очаква достигане до оптимума в повечето изпълнения (поне 8 от 10), с малка толерантност за плаваща точка.
- Решението трябва да работи за секунди дори при по-големи входове.
- Да се предвиди опция за измерване и отпечатване на времето за намиране на решението (повече подробности са налични в секцията [„Автоматично тестване“](#автоматично-тестване)).
- За примерен набор от градове можете да използвате файловете `uk12_name.csv` и `uk12_xy.csv` от архива `UK_TSP.zip`.
- Оптималното решение за набора UK12 има дължина `1595.738522033024`.

## Задача 2 — KP (раница)

### Описание

Да се реши задачата за раницата (Knapsack Problem) чрез използване на генетичен алгоритъм.

Целта е да се избере подмножество от предмети с максимална стойност, без общото тегло да надвишава вместимостта.

### Вход

| Ред | Съдържание |
|-----|------------|
| 1 | `M N` – вместимост на раницата и брой предмети |
| следващите `N` реда | по две цели числа `mi ci` – тегло и стойност на `i`-тия предмет |

### Изход

1. Поне 10 стойности (по една на ред) – текущо най-добрата стойност в популацията: първо поколение, поне осем междинни и последно поколение.
2. Празен ред.
3. Финална максимална стойност (една стойност), равна на последната от горния блок.

### Пример

**Вход:**

```
5000 24
90 150
...
2000 150
```

**Изход:**

```
1010
...
1130

1130
```

### Бележки

- Очаква се достигане до оптимума в повечето изпълнения (поне 8 от 10).
- Решението трябва да работи в рамките на секунди дори за големи входове (`N ≤ 10 000`).
- Да се предвиди опция за измерване и отпечатване на времето за намиране на решението (повече подробности са налични в секцията [„Автоматично тестване“](#автоматично-тестване)).
- Можете да използвате тестовите файлове от архива `KP.zip` – например `KP short test data.txt` и `KP long test data.txt`.
  - Първият ред във всеки файл съдържа максималната вместимост и броя на предметите.
  - За „късия“ набор: 5000 грама и 24 предмета → оптимална стойност 1130.
  - За „дългия“ набор: 5000 грама и 200 предмета → оптимална стойност 5119.

## Автоматично тестване

Използвайте конзолния инструмент **FMI AI Judge – CLI System** (страница: https://pypi.org/project/fmi-ai-judge/).

Инструментът е разработен на Python, но поддържа решения на различни езици. Той не компилира, а стартира вече компилирани изпълними файлове или скриптове. Основните езици се разпознават автоматично. Ако вашият не е сред тях, подайте команда изрично чрез:

```bash
--exec "command {src}"
```

Необходим е Python 3 (препоръчително е отделна виртуална среда с `venv`).

### Инсталация (еднократно)

```bash
pip install fmi-ai-judge
```

При обновяване на версията изпълнете:

```bash
pip install -U fmi-ai-judge
```

### Стартиране

```bash
judge run --bench path/to/solution.py
judge run --bench -p tsp path/to/solution.py
judge run --bench -p knapsack path/to/solution.py
```

> Автоматичното разпознаване гледа името на файла (напр. за TSP: `tsp`, `travelingsalesman`, `traveling-salesman`; и за Knapsack: `kp`, `ks`, `ksp`, `knapsack`, `knapsack-problem`).

### Време в изхода (опционално)

Първият ред може да съдържа ваше измерване (в милисекунди):

```
# TIMES_MS: alg=<милисекунди>
```

> Това време се включва в отчета само ако стартирате с `--bench`.

### Тестове само за време

Някои по-големи тестове са само за производителност (без пълен изход). При тях инструментът стартира решението с променлива на средата:

```bash
FMI_TIME_ONLY=1
```

Ако засечете `FMI_TIME_ONLY=1`, може да пропуснете печата на пълното решение и по желание да изведете само ред с измереното време (формата по-горе). За останалите тестове изходът трябва да е пълен и коректен.
